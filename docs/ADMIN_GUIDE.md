# راهنمای مدیر

## ورود و نقش‌ها

در اجرای کامل، ورود از Keycloak/OIDC انجام می‌شود. نقش‌های backend عبارت‌اند از:

- `admin`: تنظیمات شرکت، کاربران، امنیت، عملیات و همه داده‌های tenant؛
- `manager`: مدیریت عملیاتی و گزارش‌های تیم؛
- `supervisor`: بازبینی تماس، پیگیری و مدیریت تیم در محدوده مجاز؛
- `seller` و `agent`: تماس‌ها و کارهای مجاز خود؛
- `viewer`: مشاهده بدون عملیات تغییردهنده در endpointهای مجاز.

مجوز نهایی را پاسخ API تعیین می‌کند، نه پنهان‌شدن دکمه در UI. بعد از تغییر نقش، کاربر باید token تازه بگیرد.

## ساخت اولین مدیر

چهار متغیر `FIRST_ADMIN_EMAIL`، `FIRST_ADMIN_PASSWORD`، `FIRST_ADMIN_NAME` و `DEFAULT_TENANT_NAME` را موقتاً در `.env` تنظیم و اجرا کنید:

```powershell
docker compose run --rm api python -m app.bootstrap_admin
```

بعد از پیام `created` یا `already_exists`، رمز bootstrap را از فایل حذف کنید.

## کار روزانه پنل

1. **نمای کلی:** تعداد تماس، نرخ تکمیل، امتیاز و هشدارهای عملیات را بررسی کنید.
2. **تماس‌ها:** فیلتر فروشنده، تاریخ، نتیجه، شهر، محصول، امتیاز و وضعیت را ترکیب کنید. `failed` و `review_needed` را روزانه بازبینی کنید.
3. **جزئیات تماس:** صوت، transcript زمان‌دار، نقش، تحلیل، استخراج و شاهد را کنار هم ببینید. مقدار بدون شاهد را تأیید قطعی تلقی نکنید.
4. **پیگیری‌ها:** overdue و کارهای AI-suggested را assign/complete کنید. re-analysis نباید task تکراری بسازد.
5. **پیام‌ها:** پیش‌نویس را قبل از تأیید بخوانید. تأیید در نسخه فعلی الزاماً به معنی ارسال توسط اپراتور مخابراتی خارجی نیست.
6. **عملیات:** سلامت API/Watcher/Worker، queue، خطاهای مرحله‌ای و retry را کنترل کنید.

## اصلاح و بازتحلیل

- متن و نقش گوینده را فقط با شنیدن همان بازه صوت اصلاح کنید.
- تغییر در history ثبت می‌شود و segment به‌عنوان اصلاح انسانی علامت می‌خورد.
- برای اصلاح تحلیل بدون رونویسی دوباره، `reanalyze` را انتخاب کنید.
- برای مشکل اساسی صوت/رونویسی، `full` را اجرا کنید؛ متن اصلاح انسانی نباید ناخواسته overwrite شود، اما قبل از عملیات گسترده یک تماس را آزمایش کنید.

## KPI و Scorecard

- وزن معیارها باید دقیقاً ۱۰۰ باشد.
- نسخه جدید را ابتدا draft بسازید و پس از بازبینی فعال کنید؛ نتایج قدیمی را با نسخه prompt/scorecard خودشان تفسیر کنید.
- «نرخ تبدیل تأییدشده» فقط outcomeهای تأیید انسانی را لحاظ کند.
- WER/CER نمونه ساختگی معیار کیفیت تولید نیست؛ گزارش واقعی را از framework ارزیابی با دیتاست مرجع تولید کنید.

## اتصال‌ها و اتوماسیون

ثبت نام/نوع/وضعیت Integration در پنل به معنی اتصال عملیاتی نیست. registry اتصال CRM در نسخه فعلی connector اجرایی ثبت‌شده ندارد. قبل از فعال‌کردن هر اتوماسیون، تست اتصال، signature، retry و log واقعی همان connector لازم است.

حالت پیشنهادی پایلوت `approval` است. ارسال خودکار پیام را تا تکمیل connector و تست حقوقی/عملیاتی فعال نکنید.

## گزارش‌ها

- PDF هر تماس: `GET /api/v1/calls/{call_id}/export.pdf`
- Excel فهرست فیلترشده: `GET /api/v1/exports/calls.xlsx` با همان query filterها

در PDF فارسی، `PDF_FONT_PATH` باید به فونت فارسی قابل‌دسترسی داخل کانتینر اشاره کند؛ فایل خروجی را قبل از تحویل رسمی روی Windows و چاپ تست کنید.

## چک‌لیست روزانه مدیر پایلوت

- `/health/ready` برای API و Watcher برابر 200؛
- افزایش غیرعادی queue یا `retry_scheduled` وجود ندارد؛
- قرنطینه و خطاهای ۲۴ ساعت اخیر بازبینی شده؛
- تماس‌های `review_needed` و پیگیری‌های overdue تعیین تکلیف شده؛
- فضای دیسک و MinIO کافی است؛
- آخرین backup موفق و checksum آن موجود است؛
- کلید/رمز یا صوت واقعی در Git و log قرار نگرفته است.
